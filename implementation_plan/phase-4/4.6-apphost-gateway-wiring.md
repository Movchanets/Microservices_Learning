# 4.6 — AppHost & Gateway Wiring

> **Ref**: [plans/06-api-gateway-bff.md](../../plans/06-api-gateway-bff.md)

## Goal
Integrate the newly created `Ordering.API` and `Payment.API` into the Aspire AppHost for orchestration. YARP routes already exist in gateway config — verify they work.

## Prerequisites
- Sub-plans 4.4 and 4.5 completed
- Both `Ordering.API` and `Payment.API` are in the solution

## Steps

### Step 1: Add Project References to AppHost

```powershell
dotnet add src/Aspire/Marketplace.AppHost/Marketplace.AppHost.csproj reference src/Microservices/Ordering/Ordering.API/Ordering.API.csproj
dotnet add src/Aspire/Marketplace.AppHost/Marketplace.AppHost.csproj reference src/Microservices/Payment/Payment.API/Payment.API.csproj
```

### Step 2: Configure Aspire Orchestration

Edit: `src/Aspire/Marketplace.AppHost/AppHost.cs`

Replace the Phase 4 comment placeholders with actual project registrations:

```csharp
// Phase 4: Ordering.API
var orderingApi = builder.AddProject<Projects.Ordering_API>("ordering-api")
    .WithReference(orderingDb)
    .WaitFor(orderingDb)
    .WithReference(messaging)
    .WaitFor(messaging);

// Phase 4: Payment.API
var paymentApi = builder.AddProject<Projects.Payment_API>("payment-api")
    .WithReference(paymentDb)
    .WaitFor(paymentDb)
    .WithReference(messaging)
    .WaitFor(messaging);
```

### Step 3: Update Gateway references

Add Ordering and Payment to the gateway `WithReference` chain:

```csharp
var gateway = builder.AddProject<Projects.ApiGateway>("api-gateway")
    // ... existing references ...
    .WithReference(orderingApi)
    .WaitFor(orderingApi)
    .WithReference(paymentApi)
    .WaitFor(paymentApi)
    // ... rest of config ...
```

### Step 4: Add to Scalar API Reference

```csharp
scalar
    // ... existing references ...
    .WithApiReference(orderingApi)
    .WithApiReference(paymentApi)
    .WaitFor(orderingApi)
    .WaitFor(paymentApi);
```

### Step 5: Verify YARP routes exist

The following routes should already be in `src/Gateways/ApiGateway/appsettings.json` (from Phase 1):

```json
{
  "orderingRoute": {
    "ClusterId": "orderingCluster",
    "Match": { "Path": "/api/orders/{**catch-all}" }
  },
  "paymentRoute": {
    "ClusterId": "paymentCluster",
    "Match": { "Path": "/api/payments/{**catch-all}" }
  }
}
```

And clusters:
```json
{
  "orderingCluster": {
    "Destinations": {
      "ordering": { "Address": "http://ordering-api" }
    }
  },
  "paymentCluster": {
    "Destinations": {
      "payment": { "Address": "http://payment-api" }
    }
  }
}
```

If these already exist, no changes needed. If not, add them.

## Verification
1. Start the AppHost: `dotnet run --project src/Aspire/Marketplace.AppHost/Marketplace.AppHost.csproj`
2. Ensure the Aspire dashboard displays `ordering-api` and `payment-api` as running
3. Ensure the APIs are reachable via the Gateway URL (`/api/orders/...` and `/api/payments/...`)

## Saga Verification Checklist

After all sub-plans are complete, verify:

- [ ] **Happy path**: Cart checkout → Inventory reserved → Payment completed → Order completed
- [ ] **Compensation**: Cart checkout → Inventory reserved → Payment failed → Inventory released → Order cancelled
- [ ] **Idempotency**: Duplicate events don't create duplicate state transitions
- [ ] **Outbox**: Events survive process crash (kill service mid-transaction, verify delivery after restart)

## Done When
- [ ] `Ordering.API` and `Payment.API` are orchestrated via Aspire
- [ ] Database connections (`ordering-db`, `payment-db`) injected successfully
- [ ] Messaging (`messaging`) connected to both services
- [ ] Gateway routes requests to both services
- [ ] Scalar API Reference includes both services
