# 1.6 — Wire AppHost & Verify Full Flow

> **Ref**: [plans/04-monorepo-structure.md](../../plans/04-monorepo-structure.md) · [implementation_plan/phase-1-identity-gateway.md](../phase-1-identity-gateway.md)

## Goal
Register Identity.API and ApiGateway in the Aspire AppHost, create initial EF migration, and verify the full authentication flow.

## Prerequisites
- Sub-plans 1.1–1.5 completed

## Steps

### Step 1: Update AppHost with project references

```powershell
dotnet add src/Aspire/Marketplace.AppHost/Marketplace.AppHost.csproj reference `
  src/Microservices/Identity/Identity.API/Identity.API.csproj `
  src/Gateways/ApiGateway/ApiGateway.csproj
```

### Step 2: Update `Program.cs` in AppHost

Replace the comment block in `src/Aspire/Marketplace.AppHost/Program.cs` with actual service registrations. Add after the infrastructure declarations:

```csharp
// ──────────────────────────────────────────────
// Phase 1: Identity.API & API Gateway
// ──────────────────────────────────────────────

var identityApi = builder.AddProject<Projects.Identity_API>("identity-api")
    .WithReference(identityDb)
    .WithReference(messaging);

var gateway = builder.AddProject<Projects.ApiGateway>("api-gateway")
    .WithReference(identityApi)
    .WithReference(redis)
    .WithExternalHttpEndpoints();
```

> **Note**: Keep the placeholder comments for future phases, just update Phase 1 from comments to actual code.

### Step 3: Create initial EF Core migration

```powershell
dotnet ef migrations add InitialCreate `
  --project src/Microservices/Identity/Identity.Infrastructure `
  --startup-project src/Microservices/Identity/Identity.API `
  --output-dir Persistence/Migrations
```

> If `dotnet ef` is not installed:
> ```powershell
> dotnet tool install --global dotnet-ef
> ```

### Step 4: Build the entire solution

```powershell
dotnet build Marketplace.sln
```

**Expected**: Zero errors. All 8 projects compile.

### Step 5: Run the full stack

```powershell
dotnet run --project src/Aspire/Marketplace.AppHost
```

**Verify in the Aspire Dashboard**:
- ✅ PostgreSQL running (with identity-db)
- ✅ Redis running
- ✅ RabbitMQ running
- ✅ `identity-api` running (green health check)
- ✅ `api-gateway` running (green health check)

### Step 6: Test the Identity.API endpoints

While AppHost is running, open a new terminal:

```powershell
# Get the Identity.API URL from the Aspire dashboard, e.g. http://localhost:XXXX

# Test registration
$body = @{
  email = "test@example.com"
  password = "P@ssw0rd123!"
  firstName = "Test"
  lastName = "User"
} | ConvertTo-Json

Invoke-RestMethod -Method POST `
  -Uri "http://localhost:XXXX/api/identity/auth/register" `
  -ContentType "application/json" `
  -Body $body
```

**Expected**: Response with `accessToken`, `refreshToken`, `email`, `role`.

```powershell
# Test login
$loginBody = @{
  email = "test@example.com"
  password = "P@ssw0rd123!"
} | ConvertTo-Json

Invoke-RestMethod -Method POST `
  -Uri "http://localhost:XXXX/api/identity/auth/login" `
  -ContentType "application/json" `
  -Body $loginBody
```

**Expected**: Response with new tokens.

### Step 7: Verify health endpoints

```powershell
# Identity health
Invoke-RestMethod -Uri "http://localhost:XXXX/health"

# Gateway health
Invoke-RestMethod -Uri "http://localhost:YYYY/health"
```
