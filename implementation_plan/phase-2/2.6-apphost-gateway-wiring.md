# 2.6 — Wire AppHost, Gateway & Verify Full Flow

> **Ref**: [plans/04-monorepo-structure.md](../../plans/04-monorepo-structure.md) · [plans/06-api-gateway-bff.md](../../plans/06-api-gateway-bff.md) · [implementation_plan/phase-2-catalog-search.md](../phase-2-catalog-search.md)

## Goal
Register Catalog.API and Search.API in the Aspire AppHost, add Elasticsearch as an infrastructure resource, create EF Core migrations, and verify the full Catalog → Search event flow.

## Prerequisites
- Sub-plans 2.0–2.5 completed

## Steps

### Step 1: Add project references to AppHost

```powershell
dotnet add src/Aspire/Marketplace.AppHost/Marketplace.AppHost.csproj reference `
  src/Microservices/Catalog/Catalog.API/Catalog.API.csproj `
  src/Microservices/Search/Search.API/Search.API.csproj
```

### Step 2: Add Aspire Elasticsearch hosting package

```powershell
cd src/Aspire/Marketplace.AppHost
dotnet add package Aspire.Hosting.Elasticsearch
cd ../../..
```

### Step 3: Update `AppHost.cs`

Update `src/Aspire/Marketplace.AppHost/AppHost.cs` — replace the Phase 2 comment placeholders with actual service registrations:

```csharp
// ──────────────────────────────────────────────
// Elasticsearch — used by Search.API
// ──────────────────────────────────────────────
var elasticsearch = builder.AddElasticsearch("elasticsearch");

// ──────────────────────────────────────────────
// Phase 2: Catalog.API & Search.API
// ──────────────────────────────────────────────

var catalogApi = builder.AddProject<Projects.Catalog_API>("catalog-api")
    .WithReference(catalogDb)
    .WaitFor(catalogDb)
    .WithReference(messaging)
    .WaitFor(messaging)
    .WithEnvironment("Jwt__Issuer", "marketplace-identity")
    .WithEnvironment("Jwt__Audience", "marketplace-api")
    .WithEnvironment("Jwt__Secret", "super-secret-key-for-dev-only-min-32-chars!!");

var searchApi = builder.AddProject<Projects.Search_API>("search-api")
    .WithReference(elasticsearch)
    .WaitFor(elasticsearch)
    .WithReference(messaging)
    .WaitFor(messaging);
```

Also update the `gateway` declaration to reference both new services:

```csharp
var gateway = builder.AddProject<Projects.ApiGateway>("api-gateway")
    .WithReference(identityApi)
    .WaitFor(identityApi)
    .WithReference(catalogApi)      // ← NEW
    .WaitFor(catalogApi)            // ← NEW
    .WithReference(searchApi)       // ← NEW
    .WaitFor(searchApi)             // ← NEW
    .WithReference(redis)
    .WaitFor(redis)
    .WithEnvironment("Identity__ApiBaseUrl", "http://identity-api")
    .WithExternalHttpEndpoints();
```

> **Note**: The gateway `appsettings.json` already has routes/clusters for `catalog-api` and `search-api` (configured in Phase 1).

### Step 4: Create initial EF Core migration for Catalog

```powershell
dotnet ef migrations add InitialCreate `
  --project src/Microservices/Catalog/Catalog.Infrastructure `
  --startup-project src/Microservices/Catalog/Catalog.API `
  --output-dir Persistence/Migrations
```

> If `dotnet ef` is not installed:
> ```powershell
> dotnet tool install --global dotnet-ef
> ```

### Step 5: Build the entire solution

```powershell
dotnet build Marketplace.sln
```

**Expected**: Zero errors. Project count should include 4 Catalog projects + Search.API = 5 new projects.

### Step 6: Run the full stack

```powershell
dotnet run --project src/Aspire/Marketplace.AppHost
```

**Verify in the Aspire Dashboard**:
- ✅ PostgreSQL running (with `identity-db` and `catalog-db`)
- ✅ Redis running
- ✅ RabbitMQ running
- ✅ Elasticsearch running
- ✅ `identity-api` running (green health check)
- ✅ `catalog-api` running (green health check)
- ✅ `search-api` running (green health check)
- ✅ `api-gateway` running (green health check)

### Step 7: Seed a test category

```powershell
# First, register and login to get a JWT token
$regBody = @{
  email = "seller@example.com"
  password = "P@ssw0rd123!"
  firstName = "Test"
  lastName = "Seller"
} | ConvertTo-Json

$authResult = Invoke-RestMethod -Method POST `
  -Uri "http://localhost:XXXX/api/identity/auth/register" `
  -ContentType "application/json" `
  -Body $regBody

$token = $authResult.accessToken

# Create a category via Catalog.API
$catBody = @{
  name = "Electronics"
  description = "Electronic devices and accessories"
  sortOrder = 1
} | ConvertTo-Json

$catResult = Invoke-RestMethod -Method POST `
  -Uri "http://localhost:YYYY/api/catalog/categories" `
  -ContentType "application/json" `
  -Headers @{ Authorization = "Bearer $token" } `
  -Body $catBody

$categoryId = $catResult.id
Write-Host "Category ID: $categoryId"
```

### Step 8: Test product CRUD and event flow

```powershell
# Create a product
$prodBody = @{
  name = "iPhone 15 Pro"
  description = "Latest Apple smartphone with A17 Pro chip"
  price = 999.99
  currency = "USD"
  sku = "PHONE-IPHONE-15-PRO"
  categoryId = $categoryId
  sellerId = "00000000-0000-0000-0000-000000000001"  # Mock seller
  tags = @("apple", "smartphone", "iphone")
} | ConvertTo-Json

$productResult = Invoke-RestMethod -Method POST `
  -Uri "http://localhost:YYYY/api/catalog/products" `
  -ContentType "application/json" `
  -Headers @{ Authorization = "Bearer $token" } `
  -Body $prodBody

$productId = $productResult.id
Write-Host "Product ID: $productId"
```

**Expected**: Product created in PostgreSQL (`catalog-db`) AND `ProductCreatedEvent` published via RabbitMQ.

### Step 9: Verify Search indexing

Wait 2–3 seconds for the MassTransit consumer to process the event, then:

```powershell
# Search via Search.API
Invoke-RestMethod -Uri "http://localhost:ZZZZ/api/search/products?q=iphone&page=1&pageSize=20"
```

**Expected**: Response includes the iPhone product in search results with facets.

### Step 10: Verify via Gateway

```powershell
# Test catalog route via gateway
Invoke-RestMethod -Uri "http://localhost:GWPORT/api/catalog/products?page=1&pageSize=20"

# Test search route via gateway
Invoke-RestMethod -Uri "http://localhost:GWPORT/api/search/products?q=iphone&page=1&pageSize=20"
```

**Expected**: Both routes work through the YARP gateway.

### Step 11: Verify health endpoints
