# 7.1.1 — Identity Integration (Frontend)

> **Ref**: [implementation_plan/phase-7-frontend.md](../phase-7-frontend.md) · [src/web/Design.md](../../src/web/Design.md)

## Goal
Implement the core Authentication service, HTTP interceptor, and initial Login/Register UI flows in the Angular application. Ensure it integrates securely with the ApiGateway BFF via Cookie-based authentication.

## Prerequisites
- `7.0.1-setup-angular.md` is complete.
- ApiGateway and Identity.API are running.

## Steps

### Step 1: Scaffold Core Layer

Create the core directory structure for services and interceptors.

```powershell
cd src/web
pnpm dlx ng generate service core/auth/auth
pnpm dlx ng generate interceptor core/interceptors/auth
pnpm dlx ng generate guard core/guards/auth
```

### Step 2: Implement AuthService

Modify `src/web/src/app/core/auth/auth.service.ts` to manage the authentication state.

**Requirements:**
- Use Angular Signals (`Signal<User | null>`) for reactive user state.
- Expose methods: `login()`, `register()`, `logout()`, `checkAuth()`.
- Use Angular `HttpClient` configured with `withCredentials: true` to ensure the BFF secure cookies are sent with every request to the Gateway.

```typescript
// Example snippet logic for AuthService
import { Injectable, signal } from '@angular/core';
import { HttpClient } from '@angular/common/http';

@Injectable({ providedIn: 'root' })
export class AuthService {
  // Signal holding the current user state
  public currentUser = signal<any | null>(null);

  constructor(private http: HttpClient) {}

  // Methods for login, register, etc. passing { withCredentials: true }
}
```

### Step 3: Implement AuthInterceptor

Modify `src/web/src/app/core/interceptors/auth.interceptor.ts`.

**Requirements:**
- Ensure `withCredentials: true` is attached to all outbound requests targeting the `/api` route.
- Handle 401 Unauthorized responses globally (e.g., redirect to login or clear user signal).
- Handle CSRF tokens if required by the BFF (read from cookie, attach to header).

### Step 4: Scaffold Auth Features (UI)

Create the feature modules for Login and Register.

```powershell
pnpm dlx ng generate component features/auth/login
pnpm dlx ng generate component features/auth/register
```

**UI Requirements (per `Design.md`):**
- Use strictly Tailwind v4 classes mapped to the semantic theme (e.g. `bg-background`, `text-foreground`).
- For form inputs and buttons, prefer `@spartan-ng` directives/components where applicable.
- Ensure all static text uses the `i18n` attribute.
- Ensure validation messages are properly localized.

### Step 5: Configure App Providers & Routing

Update `src/web/src/app/app.config.ts` to provide the HttpClient and interceptor:

```typescript
import { provideHttpClient, withInterceptors, withFetch } from '@angular/common/http';
import { authInterceptor } from './core/interceptors/auth.interceptor';

export const appConfig: ApplicationConfig = {
  providers: [
    // ...other providers
    provideHttpClient(withFetch(), withInterceptors([authInterceptor]))
  ]
};
```

Update `src/web/src/app/app.routes.ts` to include the new login and register components, and apply the auth guard to a protected dummy route (e.g., `/profile`).

### Step 6: Verify Auth Flow

Run the full stack:

```powershell
cd src/Aspire/Marketplace.AppHost
dotnet run
```

1. Open the Angular app.
2. Navigate to `/register` and create an account.
3. Verify the browser receives the secure HTTP-only session cookie from the BFF.
4. Navigate to `/login` and authenticate.
5. Verify the `currentUser` signal updates and the UI reflects the logged-in state.

## Done When
- [x] `AuthService`, `AuthInterceptor`, and `AuthGuard` are implemented.
- [x] Login and Register standalone components exist and use `@spartan-ng` + Tailwind v4.
- [x] Form inputs use localized strings (`i18n`).
- [x] State is managed using Angular Signals.
- [x] End-to-end registration and login works through the API Gateway BFF.
