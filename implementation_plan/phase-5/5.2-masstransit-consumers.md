# 5.2 — MassTransit Consumers

> **Ref**: [plans/05-messaging-sagas.md](../../plans/05-messaging-sagas.md) · [plans/07-realtime-signalr.md](../../plans/07-realtime-signalr.md)

## Goal
Implement MassTransit consumers that listen to domain events from Ordering, Payment, and Inventory services, and push real-time notifications to buyers via SignalR.

## Prerequisites
- Sub-plan 5.1 completed (Hub, models, UserIdProvider)
- Phase 4 contracts exist in SharedContracts:
  - `OrderCompletedEvent` (CorrelationId, OrderId, BuyerId)
  - `OrderCancelledEvent` (CorrelationId, OrderId, BuyerId, Reason)
  - `PaymentFailedEvent` (CorrelationId, OrderId, FailureReason)
  - `InventoryReservationFailedEvent` (CorrelationId, OrderId, Reason)

## Events Consumed

| Event | Source | SignalR Message |
|-------|--------|-----------------|
| `OrderCompletedEvent` | Ordering saga | "Order Completed" |
| `OrderCancelledEvent` | Ordering saga | "Order Cancelled" + reason |
| `PaymentFailedEvent` | Payment service | "Payment Failed" + reason |
| `InventoryReservationFailedEvent` | Inventory service | "Item unavailable" + reason |

## Steps

### Step 1: Create OrderCompletedConsumer

File: `src/Microservices/Notification/Notification.Worker/Consumers/OrderCompletedConsumer.cs`
```csharp
using BuildingBlocks.SharedContracts.Events.Ordering;
using MassTransit;
using Microsoft.AspNetCore.SignalR;
using Microsoft.Extensions.Logging;
using Notification.Worker.Hubs;
using Notification.Worker.Models;

namespace Notification.Worker.Consumers;

public sealed class OrderCompletedConsumer(
    IHubContext<NotificationHub> hubContext,
    ILogger<OrderCompletedConsumer> logger) : IConsumer<OrderCompletedEvent>
{
    public async Task Consume(ConsumeContext<OrderCompletedEvent> context)
    {
        var evt = context.Message;
        logger.LogInformation("Order completed: OrderId={OrderId}, BuyerId={BuyerId}",
            evt.OrderId, evt.BuyerId);

        var message = new OrderUpdateMessage(
            evt.OrderId, evt.BuyerId, "Completed", null, DateTime.UtcNow);

        await hubContext.Clients.User(evt.BuyerId)
            .SendAsync("OrderUpdate", message, context.CancellationToken);
    }
}
```

### Step 3: Create PaymentFailedConsumer

File: `src/Microservices/Notification/Notification.Worker/Consumers/PaymentFailedConsumer.cs`
```csharp
using BuildingBlocks.SharedContracts.Events.Payment;
using MassTransit;
using Microsoft.AspNetCore.SignalR;
using Microsoft.Extensions.Logging;
using Notification.Worker.Hubs;
using Notification.Worker.Models;

namespace Notification.Worker.Consumers;

public sealed class PaymentFailedConsumer(
    IHubContext<NotificationHub> hubContext,
    ILogger<PaymentFailedConsumer> logger) : IConsumer<PaymentFailedEvent>
{
    public async Task Consume(ConsumeContext<PaymentFailedEvent> context)
    {
        var evt = context.Message;
        logger.LogWarning("Payment failed: OrderId={OrderId}, Reason={Reason}",
            evt.OrderId, evt.FailureReason);

        // PaymentFailedEvent doesn't carry BuyerId — use OrderId as the user key.
        // The frontend can match by orderId. Alternatively, query the Order store.
        // For now, send to all connected clients (buyer targeting requires OrderId→BuyerId lookup).
        var message = new OrderUpdateMessage(
            evt.OrderId, string.Empty, "PaymentFailed", evt.FailureReason, DateTime.UtcNow);

        await hubContext.Clients.All
            .SendAsync("OrderUpdate", message, context.CancellationToken);
    }
}
```

> **Note**: `PaymentFailedEvent` does not carry `BuyerId`. Options:
> 1. Send to all clients (simple, used above) — frontend filters by orderId
> 2. Query Ordering API for buyerId — adds HTTP dependency
> 3. Add `BuyerId` to `PaymentFailedEvent` in SharedContracts — **recommended** (requires Phase 4 contract update)

## BuyerId Gap Analysis

| Event | Has BuyerId? | Targeting |
|-------|-------------|-----------|
| `OrderCompletedEvent` | Yes | `Clients.User(buyerId)` |
| `OrderCancelledEvent` | Yes | `Clients.User(buyerId)` |
| `PaymentFailedEvent` | **No** | `Clients.All` (or query order store) |
| `InventoryReservationFailedEvent` | **No** | `Clients.All` (or query order store) |

**Recommendation**: Add `BuyerId` to `PaymentFailedEvent` and `InventoryReservationFailedEvent` in SharedContracts. This is a small Phase 4 contract update.
