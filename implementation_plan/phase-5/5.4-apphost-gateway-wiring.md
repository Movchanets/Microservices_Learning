# 5.4 — AppHost & Gateway Wiring

> **Ref**: [plans/06-api-gateway-bff.md](../../plans/06-api-gateway-bff.md) · [plans/07-realtime-signalr.md](../../plans/07-realtime-signalr.md)

## Goal
Register Notification.Worker in the Aspire AppHost with Redis and RabbitMQ references. Verify YARP routes for WebSocket proxying with sticky sessions.

## Prerequisites
- Sub-plan 5.3 completed (Program.cs wired)
- Notification.Worker is in the solution

## Steps

### Step 1: Add project reference to AppHost

```powershell
dotnet add src/Aspire/Marketplace.AppHost/Marketplace.AppHost.csproj reference src/Microservices/Notification/Notification.Worker/Notification.Worker.csproj
```

### Step 2: Register in AppHost.cs

Edit: `src/Aspire/Marketplace.AppHost/AppHost.cs`

Replace the Phase 5 placeholder:

```csharp
// Phase 5: Notification.Worker
var notificationWorker = builder.AddProject<Projects.Notification_Worker>("notification-api")
    .WithReference(redis)
    .WaitFor(redis)
    .WithReference(messaging)
    .WaitFor(messaging);
```

### Step 3: Add to gateway WithReference chain

```csharp
var gateway = builder.AddProject<Projects.ApiGateway>("api-gateway")
    // ... existing references ...
    .WithReference(notificationWorker)
    .WaitFor(notificationWorker)
    // ... rest of config ...
```

### Step 4: Add to Scalar API Reference

```csharp
scalar
    // ... existing references ...
    .WithApiReference(notificationWorker)
    .WaitFor(notificationWorker);
```

### Step 5: Verify YARP route

The gateway `appsettings.json` already has the notification route from Phase 1 setup:

```json
"notificationsRoute": {
  "ClusterId": "notificationCluster",
  "Match": { "Path": "/hubs/notifications/{**catch-all}" },
  "Transforms": [
    { "PathPattern": "/hubs/notifications/{**catch-all}" }
  ]
}
```

And the cluster:

```json
"notificationCluster": {
  "Destinations": {
    "destination1": { "Address": "http://notification-api/" }
  },
  "SessionAffinity": {
    "Enabled": true,
    "Policy": "HashCookie",
    "FailurePolicy": "Redistribute",
    "AffinityKeyName": "SignalR_Affinity"
  }
}
```

**No changes needed** — routes are already configured with sticky sessions.

### Step 6: Update gateway WithReference for WebSocket support

Ensure the gateway's `WithReference` chain includes `notificationWorker` so Aspire's service discovery resolves `http://notification-api` to the actual endpoint.

## Saga Verification Checklist

- [ ] SignalR negotiation (POST /hubs/notifications/negotiate) returns 200

- [ ] Publish `OrderCompletedEvent` on RabbitMQ → client receives `OrderUpdate` message
