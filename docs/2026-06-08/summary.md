# 2026-06-08 — Seeder Pipeline Fix & Variant Matrix Redesign

## Problem Statement

After running the Rozetka seeder, **5 products were created but 0 SKUs**. The `sku_errors.txt` file was empty — all error details were silently swallowed.

## Root Causes Found (4 bugs)

### 1. `File.AppendAllText` Silent Failure
`AddSkuHandler` used `File.AppendAllText(@"d:\code\Microservices\sku_errors.txt")` for debug logging. In Aspire's process context, this path was inaccessible — no exception thrown, no error visible.

**Fix**: Replaced with `ILogger<AddSkuHandler>` injected via DI.

### 2. Entity.Id = Guid.Empty Before Insert
`SkuAttributeValue.Create()` validates `skuId != Guid.Empty`. But `Entity.Id` is only generated by EF Core on insert (`GuidV7ValueGenerator`). The handler called `sku.AddOrUpdateAttributeValue()` **before** `SaveChangesAsync()` → threw `"SkuId is required"` → caught as `DUPLICATE_VARIANT` (misleading error code).

**Fix**: Moved attribute mapping **after** first `SaveChangesAsync()`.

### 3. ALL Scraped Attributes Treated as Variant Axes
The scraper treated all 14-19 laptop specs (CPU, screen, weight, etc.) as variant axes. The seeder set `VariantAxisIds` to include ALL of them. This created a massive Cartesian product and caused Select-type validation to reject values.

**Fix**:
- Added `isVariantAxis` flag to scraper output (`rozetka-scraper.ts`)
- Only `color`, `storage`, `ram` are variant axes
- Specs use `ValueType: Text` (no AllowedValues validation)
- Seeder reads classification from `catalog.json`

### 4. Variant Matrix Used Global AllowedValues
`GetVariantMatrixHandler` used `def.AllowedValues` (all values from ALL products) instead of deriving from actual SKUs. Apple's matrix showed 9 brands × 6 colors × 3 storage × 2 RAM = 324 combinations, all unavailable.

**Fix**: Always derive axis values from `GetDistinctValuesFromSkus()`. Removed `brand` from variant axes (same for all SKUs of one product).
